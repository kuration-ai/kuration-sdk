# Support

## Where to ask

Use a GitHub issue for confirmed bugs, installation failures, documentation gaps, and focused
feature requests. Search existing issues first and use the matching issue form so maintainers have
the environment and reproduction details needed to investigate.

Questions about private deployments, private datasets, account access, or commercial support need
a company-approved private support channel. No such channel is published in this repository yet;
do not put confidential information in a public issue.

Security vulnerabilities follow [SECURITY.md](https://aintropy-solutions.github.io/kuration-sdk/security/), not the ordinary issue tracker.

## What to include

- `kuration.__version__`, Python version, operating system, and installed extras;
- the smallest runnable example using synthetic or safely redacted data;
- the complete exception and the command that produced it;
- whether execution is local or Ray, in-memory or streaming, and local or cloud-backed;
- for artifact problems, the format versions and inspection output without source data.

## Support window and response expectations

The compatibility policy defines supported versions. Community support is best-effort: filing an
issue does not create a response-time or remediation SLA. Security acknowledgements and any
commercial support commitments require company-approved owners and channels before publication.
